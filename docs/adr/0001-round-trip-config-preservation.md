# Round-trip preservation when writing direwolf.conf

DireUI edits a user's existing `direwolf.conf`, which commonly contains hand-written comments and may contain directives DireUI doesn't yet recognize (Direwolf adds config options across versions). We decided DireUI's parser must track and preserve everything it doesn't explicitly change — comments, unrecognized directives, line order/formatting — and rewrite only the specific values a user edits through the UI, rather than regenerating the file canonically from DireUI's internal model. This costs more parser complexity than a generate-from-model approach, but a config editor that silently destroys a user's existing annotations on first save would undermine trust immediately, and regeneration would drop support for any Direwolf directive DireUI hasn't modeled yet.
