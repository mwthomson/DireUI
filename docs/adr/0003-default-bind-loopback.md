# Default bind address is loopback-only, despite LAN access being the primary use case

DireUI is designed for LAN reachability (headless Pi at a radio site, no auth planned for v1), which could suggest defaulting the server to bind on all interfaces (`0.0.0.0`) so it works over the LAN out of the box. We chose to default to `127.0.0.1` (loopback-only) instead, requiring the user to explicitly opt in to LAN exposure via a documented one-line config change. Since DireUI has no authentication, a LAN-open default would expose a service that can read and write a live radio config to anyone on the network immediately after install with no setup step; a safe default with a documented opt-in preserves the "easy to reach over LAN when you want it" goal while not making that exposure the unannounced default.
