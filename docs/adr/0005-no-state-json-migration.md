# No state.json migration across schema changes

DireUI's `state.json` holds Profile records, not Config File contents, so ADR-0001's round-trip preservation guarantee doesn't apply to it. Introducing Profile (a path plus a name and Last Activated time, replacing the bare-path Known Config list) breaks the existing `state.json` shape, and we decided not to write migration code — on encountering an incompatible `state.json`, DireUI starts with an empty Profile list rather than attempting to interpret the old one. This trades a one-time loss of remembered paths and the active selection for avoiding migration code that would otherwise need to keep working across every future `state.json` shape change, a trade we're only making because DireUI currently has a single user (its author) who has accepted that loss. Revisit once DireUI has users who'd be surprised by their state silently resetting on upgrade.
